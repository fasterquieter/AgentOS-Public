# AgentOS invariants

Accepted: 2026-08-26

1. **One canonical memory.** Vendor adapters may route to AgentOS; they must not carry divergent copies of project truth.
2. **The router stays small.** `AGENTS.md` maps work to knowledge and universal constraints; it is not a project encyclopedia.
3. **Progressive disclosure is measurable.** Routing must return ordered files, inclusion reasons, and estimated token cost.
4. **Uncertainty remains explicit.** Initialization must not infer product intent, invariants, architecture, or working commands from filenames alone.
5. **Evidence is not intent.** Source demonstrates current implementation; tests demonstrate exercised behavior; neither silently overrides an accepted product or architecture decision.
6. **Current truth replaces stale truth.** Active documents describe now. Plans, handoffs, and raw feedback may retain temporal evidence; obsolete working summaries are updated, archived, or deleted.
7. **Prune context, not capability.** Generic capabilities remain local and `dormant`; a project activates only the smallest project-specific adaptation justified by current evidence.
8. **No service dependency.** Core routing and validation work offline with Python's standard library.
9. **Safe adoption.** Initialization preserves existing instructions and labels unverified observations; it does not overwrite a mature repository by default.
10. **Ordinary first prompt.** In an unadapted clone, a substantive non-AgentOS product specification is sufficient to trigger agent-led adaptation; the human never has to operate AgentOS.
11. **Project-native after transition.** AgentOS self-history leaves active memory, the root router becomes project-specific, and `.agentos-kit/` recedes into dormant infrastructure.
12. **Governed self-modification.** The effective change-control policy before an edit governs that edit; an agent cannot authorize itself by weakening the policy or authority label first.
13. **One integration truth.** Parallel work may keep branch-local plans and evidence, but shared current memory is reconciled once against the merged source and tests.
14. **Failures earn routing tests.** Routing evaluation cases come from observed misses, unusable omissions, or repeated noise—not a speculative census of possible tasks.
